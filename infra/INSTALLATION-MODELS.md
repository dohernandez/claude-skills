# Skill Installation Models

All skills (except `my-workflow` itself) support two installation models. The installation model determines where config files are saved and read from.

## Models

### Standalone (external plugin)

The skill is installed directly as a Claude Code plugin. Skill files live **outside** the project, in the plugin cache.

- **How to detect**: Skill files are NOT inside `.claude/skills/<skill-name>/`
- **Config path**: `.claude/skills/<skill-name>.yaml`
- **Template/asset access**: Read from the plugin's own directory (e.g., `templates/`)

### my-workflow (copied into project)

The skill files are copied into the project by the `my-workflow` plugin. They live **inside** `.claude/skills/<skill-name>/`.

- **How to detect**: Skill files ARE inside `.claude/skills/<skill-name>/`
- **Config path**: `.claude/skills/<skill-name>/<skill-name>.yaml`
- **Template/asset access**: Must be bundled inside `skills/<skill-name>/` to be available

## Config Precedence

When reading config, check paths in this order (first found wins):

1. `.claude/skills/<skill-name>/<skill-name>.yaml` (my-workflow)
2. `.claude/skills/<skill-name>.yaml` (standalone)
3. Skill defaults

## Detection Logic

To determine the active installation model, check whether the current skill files reside inside `.claude/skills/<skill-name>/` in the project:

- **Yes** → my-workflow installation → save config to `.claude/skills/<skill-name>/<skill-name>.yaml`
- **No** → standalone installation → save config to `.claude/skills/<skill-name>.yaml`

## Documenting in a Skill

### SKILL.md

Add a **Save Location** section under the configure command:

```markdown
### Save Location

Config path depends on the installation model. Detect which model is active by checking whether this skill is running from inside `.claude/skills/<skill-name>/` (my-workflow) or from an external plugin directory (standalone).

| Installation Model | Config File | How to Detect |
|--------------------|-------------|---------------|
| **Standalone** (external plugin) | `.claude/skills/<skill-name>.yaml` | Skill files are NOT inside `.claude/skills/<skill-name>/` |
| **my-workflow** (copied into project) | `.claude/skills/<skill-name>/<skill-name>.yaml` | Skill files ARE inside `.claude/skills/<skill-name>/` |

**Precedence when reading** (first found wins):
1. `.claude/skills/<skill-name>/<skill-name>.yaml` (my-workflow installation)
2. `.claude/skills/<skill-name>.yaml` (standalone installation)
3. Skill defaults
```

### skill.yaml

Add a `config_refs` block with comments:

```yaml
# Optional project configuration generated by /<skill-name> configure
# Config location depends on installation model:
#   Standalone installation: .claude/skills/<skill-name>.yaml
#   my-workflow installation: .claude/skills/<skill-name>/<skill-name>.yaml
config_refs:
  - <config-key>          # Optional: description
```

## Exceptions

- **my-workflow** does not follow this model. It is the plugin that copies other skills into projects — it does not have a config file of its own following this pattern.
