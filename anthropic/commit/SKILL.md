# Commit Skill

## Purpose

Create standardized git commits following Conventional Commits specification. Analyzes changes to determine appropriate type, scope, and message.

## Quick Reference

- **Creates:** Git commit with conventional message
- **Requires:** Staged or unstaged changes
- **Format:** `<type>(<scope>): <subject>`

## Conventional Commit Format

```
<type>(<scope>): <subject>

<optional body - 1-2 sentences>
```

## Commit Types

| Type | Purpose | Changelog |
|------|---------|-----------|
| `feat` | New feature | Yes |
| `fix` | Bug fix | Yes |
| `docs` | Documentation only | Depends |
| `style` | Formatting/style (no logic) | No |
| `refactor` | Code refactor (no feature/fix) | No |
| `perf` | Performance improvement | Yes |
| `test` | Add/update tests | No |
| `build` | Build system/dependencies | Depends |
| `ci` | CI/config changes | No |
| `chore` | Maintenance/misc | Depends |
| `revert` | Revert commit | Yes |

## Rules

- [ ] Title ≤ 50 characters
- [ ] Title is SPECIFIC (avoid vague: "improve", "enhance", "update")
- [ ] Imperative mood ("add" not "added")
- [ ] Body: 1-2 sentences max, or omit if title is clear
- [ ] Focus on WORK done, not file operations
- [ ] Never commit secrets (.env, credentials)
- [ ] **NO AI attribution** (no Co-Authored-By, no 🤖, no "Generated by")
- [ ] **NO ticket references** (no "Fixes #123" - put in PR instead)

## AI Attribution Policy

**STRICTLY FORBIDDEN** - Never include ANY of the following in commit messages:
- `Co-Authored-By: Claude`, `Co-Authored-By: GPT`, or any AI name
- 🤖 emoji or any AI-related emojis
- "Generated by", "Created with", or similar phrases
- Any reference to AI tools (Claude, ChatGPT, Copilot, etc.)

Commits must appear as human-authored work. This is a strict project requirement.

## Workflow

### 1. Check Branch

```bash
# Refuse to commit on main/master
git branch --show-current
```

### 2. Analyze Changes

```bash
# Check status
git status --porcelain

# View staged changes
git diff --staged

# View unstaged changes
git diff
```

### 3. Stage Files (if needed)

```bash
# Stage specific files
git add path/to/file1 path/to/file2

# Stage by pattern
git add src/api/*
```

**Never stage secrets** (.env, credentials.json, private keys).

### 4. Generate Commit Message

Analyze the diff to determine:
- **Type:** What kind of change?
- **Scope:** What module/area?
- **Subject:** What did it do? (imperative mood)

### 5. User Confirmation

**ALWAYS confirm before committing:**
1. Show the generated message
2. Ask: "Commit with this message?"
3. Revise if needed

### 6. Execute Commit

```bash
# Single line
git commit -m "feat(api): add rate limiting"

# Multi-line with body (HEREDOC)
git commit -m "$(cat <<'EOF'
feat(api): add rate limiting

Limits requests to 100/minute per API key.
EOF
)"
```

## Scopes

Scopes are discovered from the project:
1. From `COMMIT_SCOPES` in skills-config.yaml (if configured)
2. From top-level directories in src/
3. From workspace packages

## Examples

**Good:**
```
feat(auth): add OAuth2 login support

Adds Google and GitHub OAuth providers.
```

```
fix(api): handle null response from external service
```

```
refactor(db): extract query builder to separate module
```

**Bad:**
- `chore: update stuff` (vague)
- `feat(api): improved performance` (vague + past tense)
- `docs: add file to docs folder` (file-focused, not work-focused)

## Changelog Awareness

When writing messages, consider changelog impact:

**Changelog-worthy (user-facing):**
```
feat(api): add webhook notifications
fix(auth): prevent session timeout during checkout
chore(deps): upgrade axios to fix security vulnerability
```

**Internal (dev-only):**
```
chore(ci): add parallel test execution
test(api): add rate limiting tests
docs: update development setup instructions
```

## Git Safety

- **NEVER** commit directly to main/master
- **NEVER** update git config
- **NEVER** run destructive commands without explicit request
- **NEVER** skip hooks unless user asks
- **NEVER** force push to protected branches
- If hook fails: fix issue, create NEW commit (don't amend)

## Anti-Patterns

| Pattern | Why Bad |
|---------|---------|
| Vague subject ("improve", "update") | Useless in git log |
| Past tense ("added", "fixed") | Not imperative mood |
| File-focused ("add file to...") | Should describe work, not files |
| Long title (>50 chars) | Gets truncated |
| Staging secrets | Security risk |
